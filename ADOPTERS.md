# Adopters

This file records known adopters of **Purser** — organizations and projects
using it, whether in production or under active evaluation. It exists so the
community and prospective users can see real-world usage, and so foundations
(e.g. CNCF) can gauge adoption. Listing is **voluntary and self-reported**.

## Current adopters

_Purser is early — no adopters are listed publicly yet._

If your organization uses Purser, we would love to add you. Both **production**
and **evaluation / proof-of-concept** usage are welcome and valuable.

Column guidance:
- **Organization / Project** — your name, or "Anonymous, <sector>" if you cannot
  be named publicly (e.g. "Anonymous, financial services").
- **Since** — approximate month/year you started using Purser.
- **Use case** — e.g. "CI gate on model registry promotions", "Kubernetes
  admission enforcement", "pre-download scanning of HuggingFace models".
- **Environment** — e.g. CI, Kubernetes, CLI, REST API; production vs. evaluation.
- **Reference** — optional link (blog post, talk, repo) or a contact handle.

## How to be added

Open a pull request adding a row above with whatever detail you are comfortable
sharing. Anonymous and sector-only entries are accepted. Alternatively, open an
issue or email **security@purser-io.io** and a maintainer will add you. You can
ask to be removed at any time the same way.

Adopter entries are self-attested; Purser does not audit or endorse listed
users, and listing does not imply any support relationship.
